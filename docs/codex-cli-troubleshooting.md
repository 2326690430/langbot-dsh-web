# Codex CLI 故障排除和最佳实践指南

本文档提供了使用Codex CLI与LangBot集成时的常见问题解决方案和最佳实践建议，帮助您获得更顺畅的开发体验。

## 常见问题及解决方案

### 1. 连接问题

#### 症状：无法连接到LangBot MCP服务器
- **可能原因**：
  1. LangBot实例未运行
  2. MCP端点URL错误
  3. 网络防火墙阻止连接
  4. 端口被其他进程占用

- **解决步骤**：
  1. 验证LangBot实例是否正在运行：
     ```bash
     # 检查LangBot进程
     ps aux | grep langbot
     # 或检查Docker容器
     docker ps | grep langbot
     ```
  2. 确认MCP端点URL正确：
     - 默认本地开发端点：`http://localhost:5300/mcp`
     - 在LangBot Web面板的 **API & MCP** 选项卡中查看确切地址
  3. 测试网络连接：
     ```bash
     # 替换为您的实际端点
     curl -X GET http://localhost:5300/mcp/health
     # 或简单测试端口连通性
     telnet localhost 5300
     ```
  4. 检查防火墙设置，确保允许到LangBot端口（默认5300）的连接

#### 症状：间歇性连接丢失
- **可能原因**：
  1. 网络不稳定
  2. 服务器负载过高导致超时
  3. 客户端未实现心跳机制

- **解决步骤**：
  1. 检查网络连接稳定性
  2. 查看LangBot服务器日志是否有超时或负载警告
  3. 在Codex CLI使用中实现定期心跳（如果支持）
  4. 考虑增加超时时间或实现重试机制

### 2. 认证问题

#### 症状：认证失败或未授权错误
- **可能原因**：
  1. API密钥错误或已过期
  2. API密钥权限不足
  3. 认证信息未正确传递
  4. 使用了错误的认证方法

- **解决步骤**：
  1. 验证API密钥是否正确：
     - 在LangBot Web面板中重新检查API密钥
     - 确保没有多余的空格或字符
  2. 检查API密钥是否已过期（如果适用）
  3. 确认API密钥具有访问MCP端点所需的权限
  4. 验证认证配置是否正确：
     - 如果使用环境变量：`echo $CODEX_MCP_LANGBOT_API_KEY`
     - 如果使用配置文件：检查JSON格式和值
  5. 尝试重新生成API密钥并更新配置

#### 症状：令牌刷新问题（长时间会话）
- **可能原因**：
  1. 访问令牌过期未自动刷新
  2. 刷新令牌无效或已过期
  3. 认证服务不可达

- **解决步骤**：
  1. 检查是否需要手动刷新令牌
  2. 查看LangBot的令牌过期策略
  3. 实现令牌自动刷新机制（如果Codex CLI支持）
  4. 考虑使用较短的会话并在需要时重新认证

### 3. MCP协议问题

#### 症�：方法不存在或无效参数
- **可能原因**：
  1. 使用了错误的MCP方法名称
  2. 参数格式不正确
  3. 方法需要特定权限但未授予
  4. MCP服务器版本不支持该方法

- **解决步骤**：
  1. 验证方法名称是否正确：
     - 使用 `codex mcp list` 查看所有可用服务器
     - 使用 `codex mcp info langbot` 查看服务器详情
     - 查看LangBot MCP文档了解正确方法名称
  2. 检查参数格式是否为有效JSON
  3. 确认您的API密钥具有执行该方法所需的权限
  4. 查看LangBot版本与MCP方法的兼容性

#### 症状：响应数据格式异常
- **可能原因**：
  1. MCP服务器返回非JSON数据
  2. 网络传输过程中数据损坏
  3. 客户端期望的数据结构与实际不符

- **解决步骤**：
  1. 启用Codex CLI的调试模式查看原始响应
  2. 检查是否有网络中断或数据包丢失
  3. 验证您期望的数据结构与LangBot实际返回的一致性
  4. 考虑添加数据验证和容错处理

### 4. 性能问题

#### 症状：响应缓慢或超时
- **可能原因**：
  1. 网络延迟高
  2. 服务器处理负载大
  3. 查询过于复杂或数据量过大
  4. 缺少适当的索引或优化

- **解决步骤**：
  1. 测试网络延迟：`ping` 或 `traceroute` 到LangBot服务器
  2. 查看LangBot服务器性能监控（如果可用）
  3. 简化查询或分页获取大数据集
  4. 检查是否可以添加过滤条件减少返回数据量
  5. 考虑实现本地缓存减少重复请求

#### 症状：高频率请求导致速率限制
- **可能原因**：
  1. 未实现请求节流
  2. 批量操作未合并
  3. 触发了LangBot的速率限制保护

- **解决步骤**：
  1. 实现请求间隔或使用令牌桶算法
  2. 将多个操作合并为单个批量请求（如果支持）
  3. 检查LangBot是否有可配置的速率限制阈值
  4. 添加重试逻辑和指数退避策略

## 最佳实践

### 1. 安全最佳实践

#### API密钥管理
- **不要**在代码或配置文件中硬编码API密钥
- 使用环境变量或安全的密钥管理服务（如HashiCorp Vault, AWS Secrets Manager）
- 定期轮换API密钥（建议每30-90天）
- 为不同环境（开发、测试、生产）使用不同的API密钥
- 授予最小必要权限，而非全局管理员权限

#### 数据保护
- 在传输过程中使用HTTPS/WSS加密连接
- 生产环境中避免使用明文API密钥
- 注意日志中不要意外记录敏感信息
- 考虑在客户端实现数据加密存储（如果需要持久化凭据）

### 2. 配置管理

#### 环境分离
- 为开发、测试、生产环境维护独立的配置文件
- 使用配置模板（template）而不包含实际敏感数据
- 考虑使用配置管理工具（如Consul, Etcd）处理复杂配置

#### 版本控制
- 将配置文件模板添加到版本控制中（但排除实际密钥文件）
- 使用`.gitignore`防止意外提交敏感信息
- 考虑使用环境变量文件（.env）及其模板（.env.example）

### 3. 错误处理和调试

#### 健壮的错误处理
- 实现全面的异常捕获和错误恢复机制
- 区分暂时性错误（网络抖动）和永久性错误（认证失败）
- 提供有意义的错误消息以便快速定位问题
- 考虑实现重试机制和指数退避策略

#### 调试技术
- 启用Codex CLI的verbose或debug模式获取详细日志
- 使用网络抓包工具（如Wireshark, tcpdump）分析通信细节
- 查看LangBot服务器日志了解服务器端的处理情况
- 创建最小可重复示例（MRE）来隔离问题
- 使用断点和单步调试（如果适用）追踪执行流程

#### 监控和告警
- 实现关键操作的成功/失败率监控
- 设置异常情况的告警通知（如连接失败率超过阈值）
- 记录性能指标（响应时间、吞吐量）用于容量规划
- 考虑使用分布式追踪工具了解跨服务调用链

### 4. 性能优化

#### 连接管理
- 重用MCP连接而非为每个请求创建新连接
- 实现连接池以处理并发请求
- 监控连接状态并在需要时重新建立连接
- 考虑使用长轮询或WebSocket保持持久连接（如果支持）

#### 请求优化
- 批量相关操作以减少往返次数
- 使用适当的查询参数限制返回数据量（分页、过滤、字段选择）
- 缓存经常访问且变化不频繁的数据
- 考虑使用条件请求（如ETag, Last-Modified）避免不必要的数据传输

#### 资源管理
- 及时关闭不再使用的连接和资源
- 监控内存使用防止泄漏
- 考虑使用对象池减少频繁创建销毁开销
- 优化算法和数据结构选择

### 5. 开发工作流

#### 本地开发
- 使用专门的开发环境避免影响生产数据
- 创建数据库和配置的本地副本进行测试
- 实施功能开关逐步引入新特性
- 使用容器化（Docker）确保环境一致性

#### 测试策略
- 编写单元测试验证逻辑正确性
- 创建集成测试确保与LangBot的交互正常
- 实施端到端测试覆盖完整工作流
- 使用模拟框架（如jest, pytest-mock）隔离外部依赖
- 在CI/CD管道中自动执行测试

#### 部署和发布
- 使用蓝绿部署或滚动更新最小化服务中断
- 实施金丝雀发布逐步验证新版本
- 准备回滚计划以快速恢复到已知良好状态
- 编写详细的发布说明和升级指南

## 故障排除工作流程

当遇到问题时，请按照以下步骤进行系统性排查：

### 步骤1：收集信息
- 记录确切的错误消息和时间戳
- 确认受影响的操作和频率
- 收集相关的日志和监控数据
- 重现问题的步骤（如果可能）

### 步骤2：初步诊断
- 验证基本连接性（网络、服务器可达性）
- 检查服务状态（LangBot是否运行正常）
- 确认认证信息是否有效
- 查看是否有明显的配置错误

### 步骤3：深入分析
- 启用调试模式获取详细信息
- 检查协议交互细节（请求/响应内容）
- 查看服务器端日志了解处理情况
- 分析是否为间歇性问题还是持续性问题

### 步骤4：解决和验证
- 根据分析结果应用相应的修复措施
- 在受控环境中测试修复效果
- 验证修复不会引入新问题
- 更新文档和知识库以防止类似问题重复发生

### 步骤5：预防措施
- 识别根本原因以防止类似问题再次发生
- 考虑添加监控和告警以提前发现问题
- 更新最佳实践和操作指南
- 分享经验教训给团队成员
